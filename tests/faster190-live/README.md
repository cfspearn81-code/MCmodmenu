Aim Lock regression on a real Minecraft 26.3/Fabric client at 854×480, connected to a disposable vanilla dedicated localhost server at 127.0.0.1:25568 with offline OP BridgeLive. Production selection, rotation, camera hooks, menu hit-testing and settings run unchanged. Two client-only RemotePlayer entities provide deterministic head positions, poses and visibility; these are fixture targets, not additional network-connected accounts. The local player's actual vanilla outgoing movement/look packets are observed. This does not test a public server or third-party anti-cheat.

results.txt and run-summary.txt record the passing final run. Coverage includes:

- Search and Combat toggles, function-key and letter-key binding, and existing Bridge/Free Cam binding controls.
- No aiming without the hold key; selecting the nearest unobstructed player's head; switching when another player moves closer; crouching head height.
- Skipping invisible, dead and block-occluded players, including selection behind the original view.
- Immediate manual control on key release; pausing for the P menu, Free Cam and window focus loss; disabled-module behavior and clearing a stale target when no valid players remain.
- 437 camera frames with both actual player view and camera direction aligned to the selected interpolated head. Assertions use the render frame's partial tick and normalize the native player view vector because Minecraft's trigonometric lookup can return a slightly non-unit vector.
- 14 native look packets during the measured scenarios, each matching actual player yaw/pitch; at most one movement packet per player tick and zero attack-interaction packets.

HoldMixin substitutes only physical hold-key state so the fixture can exercise release deterministically. CameraMixin verifies camera output after native alignment, PacketMixin observes outgoing packets, and GameMixin drives the scenario and focus state. Menu rebinding uses the normal KeyboardHandler callbacks and production click handling. All other gameplay modules are disabled for isolation; Aim Lock finishes disabled with its default R binding.

To reproduce, start the disposable offline vanilla server above and grant BridgeLive OP. Compile src/ with JDK 25 against the built production client classes and the Minecraft/Fabric runtime classpath. Copy fabric.mod.json and check.mixins.json into a clean fixture classes directory and create a fixture JAR. Launch runClient with -Dfabric.addMods=/absolute/path/fixture.jar appended to JAVA_TOOL_OPTIONS and --username BridgeLive --width 854 --height 480. SDL_VIDEODRIVER=offscreen and ALSOFT_DRIVERS=null support cloud rendering. The fixture connects automatically, prepares a stone arena around (-255.5,120,-255.5), adds its client-only targets, creates an occlusion wall through ordinary OP commands, writes /tmp/faster190-live/results.txt and screenshots, and stops after AIM ALL CHECKS COMPLETE. It modifies only the disposable test world and test-client settings. These fixture sources and classes are outside production roots and excluded from the release JAR.
