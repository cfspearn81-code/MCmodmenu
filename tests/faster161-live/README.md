The user report identifies `IllegalStateException: Can only blur once per frame` in PauseScreen.extractBackground, after ClientMenu's HUD overlay had already requested a background blur. The tick-only close could miss a screen opened between ticks. The fix dismisses the custom menu at Gui.setScreen/setOverlay HEAD, before vanilla changes mouse ownership, and also checks screen/overlay/player state before drawing or updating the custom cursor. It retains the ordinary P-menu blur and vanilla pause background, without swallowing exceptions or globally altering the blur renderer.

The fixture opens each normal screen inside Gui.extractRenderState HEAD, after a custom menu has opened and BEFORE the HUD/screen are drawn, with no intervening Minecraft tick. All eight transition frames close safely and leave the mouse released for the native screen. Pause frames make exactly one vanilla blur request; inventory frames make none, matching Minecraft 26.3. Across the whole run no frame makes more than one blur request, and P-menu frames still make exactly one. An overlay-opening test verifies immediate dismissal before any tick.
