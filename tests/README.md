This branch restores the 1.3.5 source archive and adds nametag-matched ESP outlines. `NametagColorTest.java` exercises actual Minecraft Components, including inherited team colors, differently colored rank prefixes, custom RGB and dynamic updates. It can be compiled/run using JDK 25 and the game/dependency classpath, or run in the Fabric prelaunch test fixture. The original movement classes are compared byte-for-byte against the saved original 1.3.5 JAR after building. Later 1.3.6–1.3.8 working files/tests were archived outside the checkout at `/workspace/backups/mcmodmenu-before-esp-on-1.3.5/v1.3.8-working-files.tar.gz` before restoration.

Auto Hit adds `AttackCadenceTest.java` (seven cooldown/duplicate/burst checks) and `AutoHitSettingsTest.java` (default off, preservation across all other setters, and fresh-process reload). Settings tests use the isolated `tests/support` loader/logger stubs with `-Dtest.config` pointing at a disposable directory; do not run them against the game’s actual config directory. These stubs are outside Gradle production source roots and are never packaged.

The Fabric prelaunch check validates that the Minecraft attack invoker applies and Auto Hit loads. It stops before graphical gameplay; it does not establish real-server combat behavior or server-specific attack-rate acceptance. The implementation uses the normal client attack handler and fully charged vanilla weapon cooldown, rather than a claimed universal server CPS maximum.

CursorTrailTest exercises nine fade/reset/bounds cases without Minecraft dependencies. tests/menu-visual contains the disposable real-client screenshot/focus test fixture and validation notes.

The ui.2 edge fix intentionally changes AutoBridge and adds BridgeEdgeGuard plus its player-movement mixin. Earlier byte-identical bridge checks apply to ui.1; ui.2 preserves targeting, timing, GUI, ESP and Auto Hit, while changing the safety checks. BridgeEdgeGuardTest covers 72 swept angles plus retreat, gap, confirmed-path and pending-footing checks.

ui.3 adds GuiMoveSettingsTest for legacy configuration migration and explicit-new-setting precedence. The live movement/screens/tracer fixture and its validation limits are documented in tests/guimove-live/README.md. Production bridge, Auto Hit, cursor, paint and nametag-color resolver classes were verified byte-identical to ui.2.

1.3.5-xray.1 adds XraySettingsTest (default 200/off, exact 1–5000 validation, filter preservation and fresh-JVM persistence) and tests/xray-live for actual loaded-chunk scans, ore/variant matching, GUI controls and through-wall screenshots. Xray is independent of Player ESP and its settings file.

1.3.5-xray.2 replaces periodic scans/per-edge GUI states with an event-driven compact cache and one batched overlay. OreMeshTest covers coordinate bounds, duplicate edges, distinct ore colors, dense mesh size and sparse/dense mutation indexes; OreProjectionTest covers near/screen clipping, finite vertices, retained far-range visibility and behind-camera rejection. tests/xray-performance documents the reproduced overlap-check stall and live stationary/moving measurements. The existing xray-live fixture now reads the compact cache and checks immediate removal/new ore discovery in a previously empty section.
