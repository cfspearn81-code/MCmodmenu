Performance regression verification for 1.3.5-xray.2 on a real Fabric 26.3 client and disposable localhost vanilla server. Measurements are from a cloud OpenGL/Mesa offscreen client at 1280×720, GUI scale 2. They are not a guarantee of a particular FPS on another computer.

The old renderer created one transformed GUI rectangle per visible edge: up to 4096×12 = 49152 elements, before clipping. The dense test filled two adjacent 32×32×32 volumes with coal ore, X=-32..31, Y=65..96, Z=8..39. BridgeLive stood at 0.5,81,0.5 looking +Z. With the original released renderer, the render thread was still in GuiRenderState.hasIntersection/navigateToAboveHighestElementWithIntersectingBounds when sampled at a process age of 179 seconds, with 163 seconds of render-thread CPU. That run was terminated; it did not yield a valid completed dense FPS average. before-dense-stack.txt preserves the relevant stack. A second reproduction also remained in the same overlap path and was terminated. The optimization removes that per-edge overlap scheduling.

The sparse old baseline (18 ore blocks, before.json) averaged 0.4075 ms of extraction, 80066 allocated bytes and 213 GUI elements per frame. This is a different scene from the dense measurements and must not be used to claim an FPS percentage improvement.

The optimized dense run completed 120 sampled frames. after-dense.json records 0.0325 ms mean extraction (p95 0.0965 ms), 469 allocated bytes per extraction, one GUI element, 0.0142 ms mean Xray tick and 1.1842 ms mean vertex construction. after-moving.json repeats the dense test with yaw oscillating ±30 degrees: 0.8584 ms extraction, 1.0609 ms vertex construction and one element. The additional final-dense-moving.json confirms the final build after bounded queue generation was added: 1.2233 ms mean extraction (p95 3.1480 ms), 1.1315 ms vertex construction, 0.0074 ms mean tick and one element. This final fixture JAR contains only bench/ classes and test metadata, with no duplicate production helpers. Full frame intervals include all Minecraft work and software rendering, not just Xray. Extraction and vertex construction are separate stages: reporting extraction alone as total Xray CPU would be misleading.

The benchmark uses ThreadMXBean allocation counts and timed test mixins around Xray.tick/render and OreOutlineState.buildVertices. GUI elements are counted at GuiRenderState.addGuiElement while Xray submits its overlay. It does not replace the renderer, scanner, or block data. The fixture sets focus true, turns other modules off, issues normal OP fill/teleport commands in the disposable world and samples after 100 ticks. To reproduce, compile src/ against the client classes and Minecraft/Fabric classpath, copy both JSON resources into the fixture classes directory, and jar them. Launch runClient with -Dfabric.addMods=/path/to/fixture.jar and -Dbench.output=/tmp/result.json in JAVA_TOOL_OPTIONS, --username BridgeLive. Add -Dbench.motion=true for camera movement. Use a loaded/force-loaded X=-32..31,Z=0..48 area, an OP offline BridgeLive account and server bound to 127.0.0.1:25568. It modifies the disposable world and test-client settings; never install it in a normal game.

Core changes: immutable primitive edge meshes deduplicate same-color shared edges; one normal GUI element emits all line quads directly without per-edge matrices, AABBs, vectors, lists or GUI nodes. Cached candidates refresh at most 10 Hz during movement, while projection follows the camera every frame. Compact ore caches scan each unchanged loaded section once and update from block/chunk events. A bitset tracks unscanned sections; only loaded chunks are sorted, and section work is generated gradually under a soft tick budget. All-disabled filters and disabled Xray perform no scanning/drawing. Dense sections use a lazy local-position index for constant-time block updates.

OreMeshTest and OreProjectionTest validate deduplication without changing ore colors, all coordinate extremes needed by the 5000-block radius, sparse/dense updates, near-plane/viewport clipping and visibility beyond vanilla's terrain far plane. tests/xray-live validates all nine colors, filters, typed bounds, copper exclusion, immediate removal, new ores in an already-scanned empty section, and clearing the cache on disable. Rendered screenshots were visually inspected and pixel-checked. These tests use a local server, not an authenticated public server.
