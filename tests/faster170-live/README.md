QuickJump verification for Faster 1.7.0, on a real Fabric/Minecraft 26.3 client at 854×480 connected to a disposable vanilla server at 127.0.0.1:25568, offline OP BridgeLive. The fixture uses normal key mappings, production player physics, block collisions and jump callbacks. It observes server correction packets without suppressing them. OP commands only prepare the disposable arena/effects and teleport between cases; the mod adds no packet loop or teleport command.

The baseline and QuickJump use the same actual jump:

- Default: normal jump rises 0.4199999869 on tick 1 and peaks at 1.2522033403 on tick 6. QuickJump reaches exactly 1.2522033403 on tick 1, then falls normally.
- Jump Boost I: normal peak 1.8361316070 on tick 7; QuickJump reaches that same peak on tick 1.
- An overhead block limits the first rise to 0.2000000477 (the actual player/ceiling gap), with no passage through the ceiling.
- A one-block ledge is reached with the normal movement keys; the actor lands on top at Y82. Forward input is released before the ledge ends, avoiding a subsequent walk off its far side.

results.txt records all completed scenarios and server-correction counts; trajectories.csv preserves per-tick rise, vertical velocity and grounded state. Additional passing cases cover holding Space/repeated grounded jumps without increasing the peak, QuickFall enabled during a QuickJump, Wall Climb retaining ladder movement, Free Cam moving vertically without jumping the body, and ordinary swimming motion. First-tick getPosition(0) is also checked to equal the new height, so interpolation cannot make the accelerated ascent display as a gradual rise.

The UI types quickjump into the actual focused search, verifies one result, clicks its switch on/off, opens Movement, scrolls to the new module and clicks that switch both ways. Search and Movement screenshots are visually inspected outside the repository at /workspace/previews/faster-1.7.0/.

QuickJumpPhysicsTest validates the exact default peak, boosted/reduced-surface heights, small-velocity timing and bounded fallback for unsupported/extreme gravity/drag/height. QuickJumpSettingsTest uses tests/support and an isolated -Dtest.config directory across three fresh processes to check default-off, enabled persistence and disabled persistence. The Gradle build passes. The release JAR's existing non-menu classes are byte-identical to 1.6.1, with only the new QuickJump classes/mixin added to gameplay code; test fixtures are excluded.

To reproduce, run the disposable offline OP server above with a safe floor at 0.5,81,-20.5 and the Wall Climb stone wall at X8,Y81..120,Z3 over a Y80 floor. The fixture builds the rest of its arena through fill commands, including a clear path above the one-block ledge (old Wall Climb test walls must not obstruct it). Compile src/ against the production client classes plus Minecraft/Fabric runtime dependencies with JDK25, copy fabric.mod.json and check.mixins.json into a CLEAN fixture class directory and jar it. Launch runClient with -Dfabric.addMods=/absolute/path/fixture.jar in JAVA_TOOL_OPTIONS and --username BridgeLive --width 854 --height 480. SDL_VIDEODRIVER=offscreen and ALSOFT_DRIVERS=null support cloud software rendering. It changes test-client settings and the disposable actor's jump effect, writes /tmp/faster170-live/results.txt and trajectories.csv, resets the new toggle to off and stops after JUMP ALL CHECKS COMPLETE. These are local vanilla server checks, not a test of every server's movement rules.

All eleven physics cases finished with zero unexpected server corrections. Holding Space produced seven grounded jumps with the same 1.2522033403 peak. The QuickFall combination retained normal jump descent; Wall Climb rose 4.4184 blocks, Free Cam kept the body at its original height, and the first swimming movement rose only 0.035 rather than an instant jump peak.
