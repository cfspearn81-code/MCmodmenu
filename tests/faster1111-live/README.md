Run the Faster 1.11.1 client against a disposable vanilla Minecraft 26.3 server on `127.0.0.1:25568` with the offline operator `BridgeLive`. The fixture prepares a platform and supplies keyboard input. It checks actual movement and placement interactions, including the four-tick interaction interval, lack of aim changes, and preservation of trusted footing.

The delayed-acknowledgement case holds acknowledgement for twelve ticks while delivering the solid server block state normally. Acknowledgement and stability must both be present before movement advances. The fixture checks that progress exceeds the 1.11.0 baseline, which travelled 7.64 blocks in the same 180-tick interval. The other placement cases cover prompt acknowledgement, rejection, key release, missing block proof, delayed block updates and late removal after four clean placements.

A real server teleport tests the position correction handler on the platform. A simulated server velocity packet exercises Minecraft's normal velocity handler with a small horizontal push. Both keep the bridge key and walking input held while checking the pause. The fixture verifies the corrected position or applied impulse, checks that further placement and walking input stop, and releases and presses the bridge key on solid ground to verify resumption. These cases exercise corrections on a platform rather than implying the client can undo a displacement into the void.

Compile `src/` against the built client classes and Minecraft/Fabric runtime classpath with JDK 25. Copy `fabric.mod.json` and `check.mixins.json` into the fixture classes directory and package a fixture JAR. Launch `runClient -x downloadAssets` with `-Dfabric.addMods=/absolute/path/to/fixture.jar` in `JAVA_TOOL_OPTIONS` and `--username BridgeLive --width 854 --height 480` as the client arguments. `SDL_VIDEODRIVER=offscreen` and `ALSOFT_DRIVERS=null` support a headless run. Results go to `/tmp/faster1111-live/`. The fixture exits after `GHOST ALL CHECKS COMPLETE`.

The final run passed all 14 local cases. With acknowledgement delayed, the bridge covered 10.89 blocks in 180 movement ticks, compared with 7.64 in the 1.11.0 run. The prompt-acknowledgement case covered 11.64 blocks in both runs.
