Run the Faster 1.11.0 client against a disposable vanilla Minecraft 26.3 dedicated server at `127.0.0.1:25568` with the offline operator `BridgeLive`. The fixture builds platforms and supplies held movement and bridge input. The player holds a level view throughout. Auto Bridge picks every placement while the fixture measures interactions and actual player position.

The fixture covers straight and diagonal bridging, delayed acknowledgement, rejected placements, release while waiting, early and late server removals, withheld block updates, and false solid states that persist after acknowledgement. It also checks diagonal jumping toward unconfirmed manual predictions. In the consecutive-placement rollback case the server accepts four blocks, then removes the fifth eight ticks after acknowledgement. The client must stay over the last trusted block. Assertions enforce a four-tick placement interval and check that the player does not fall below the test platform.

Vanilla confirms and rejects the real interactions. The fixture simulates missing or delayed feedback by intercepting the client handlers. Server removal uses the vanilla `setblock` command. This tests specific faults reproducibly on a local server. A server can still remove a block after the player has stepped onto it.

Compile `src/` with JDK 25 against the built client classes and Minecraft/Fabric runtime classpath. Copy `fabric.mod.json` and `check.mixins.json` into the fixture classes directory and build a fixture JAR. Launch `runClient -x downloadAssets` with `-Dfabric.addMods=/absolute/path/to/fixture.jar` in `JAVA_TOOL_OPTIONS` and `--username BridgeLive --width 854 --height 480` as the arguments. `SDL_VIDEODRIVER=offscreen` and `ALSOFT_DRIVERS=null` support a headless run. Output goes to `/tmp/faster1110-live/`, and the client exits after `GHOST ALL CHECKS COMPLETE`.

All twelve scenarios passed at the platform height. The archived results combine the first four scenarios and a second run starting with rollback (`-Dghost.start=4`). The fixture was corrected between runs to schedule a new rollback for each retry. Both runs used the same production classes. The build and both footing and swept-edge unit checks passed.
