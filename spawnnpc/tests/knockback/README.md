Spawn NPC 1.1.0 opt-in knockback regression on a real Minecraft 26.3/Fabric client at 854×480 connected to a disposable vanilla localhost server at 127.0.0.1:25568, offline OP BridgeLive. Run once as the standalone mod without Faster and once using the built release JAR alongside Faster 1.9.4. Production command, hit handling, physics, picking and cleanup run unchanged. The fixture supplies native chat Enter/click input, prepares its arena through ordinary OP commands and observes outgoing packets. This is a local client test, not a server damage or anti-cheat simulation.

The inherited 1.0.0 cases check skin/equipment cloning, ordinary fixed-dummy hits, mainhand/offhand diamond behavior, repeated clicks after despawn, multi-NPC placement/isolated removal, invalid arguments, entity-ID replacement, normal server command/entity forwarding, dimension cleanup and packet isolation. A delayed position check proves plain /spawnnpc remains fixed after hits, rather than checking only the immediate click frame. Unsupported `kb extra` and uppercase `KB` show usage.

New cases submit `/spawnnpc kb` through the real chat screen, including normalized whitespace, and check that a later plain spawn retains its separate fixed mode. Before a hit the KB dummy must remain still and grounded. An actual native left click must produce outward/upward velocity; subsequent game ticks must show displacement and rising height, collision-free travel, landing at the starting ground height and drag reducing horizontal motion. Health stays at 20. The concurrently spawned plain dummy remains fixed, even after being hit.

A second hit after landing must launch again. A native diamond-block click must fully remove the KB dummy while airborne without consuming the item. Separate scenarios check a full-height stone wall blocking its motion and a diagonal hit pushing away from the attacker's position on both horizontal axes. In integration mode production Faster Aim Lock must select and retain the moving KB target. Actual server-driven dimension transition clears all remaining NPCs. No local /spawnnpc command packet or NPC attack/interact packet may reach the server; ordinary server commands and attacks still pass through. Vanilla swing packets may still occur.

RemotePlayer normally interpolates network movement rather than integrating local physics. Only KB dummies call native player travel, and their downward velocity is cleared on floor contact so it cannot accumulate and cancel a later hop. Plain dummies continue the old path. The inherited three-argument TestNpc constructor defaults to fixed mode.

Compile src/ against the built Spawn NPC client classes plus Minecraft/Fabric dependencies with JDK25, copy fabric.mod.json/check.mixins.json into a clean fixture classes directory, and jar it. Start the disposable offline OP server above. Launch the standalone project's runClient with `-Dfabric.addMods=/absolute/path/fixture.jar` in JAVA_TOOL_OPTIONS and --username BridgeLive --width 854 --height 480. For integration use Faster's runClient with `-Dfabric.addMods=/absolute/path/spawnnpc-1.1.0-mc26.3.jar:/absolute/path/fixture.jar`. SDL_VIDEODRIVER=offscreen and ALSOFT_DRIVERS=null support cloud rendering. The fixture resets its actor to the Overworld, prepares its arena, records results/screenshots under /tmp/spawnnpc110-live/, clears test Aim Lock input/settings and stops after NPC ALL CHECKS COMPLETE. Optional -Dnpc.kbOnly=true skips inherited cases for focused physics diagnostics. Archived final runs exercise the full list without that flag.
